# Домашнее задание: Написание тест-кейсов для тренажёра Авито

## Цель задания
Научиться анализировать требования и писать на их основе тестовую документацию.

## Вводные для выполнения ДЗ
- **[Требования к проекту:](https://docs.google.com/document/d/1IZ9SxEcePoQT6lyEmukycp1qNok4HZtok73UQnPwKSA/edit?tab=t.0#heading=h.d2wutio4bbtq)** 
- **[Дизайн проекта в Figma:](https://www.figma.com/design/Cpp1I80K2KyiFwQTlZN8hU/TestBoard2?node-id=0-1&p=f&t=fu5fOAp3qECTTodT-0)** 

## Как выполнять ДЗ?
1. Откройте [шаблон для выполнения ДЗ](https://docs.google.com/spreadsheets/d/1UbvpkRLsAdDsaWGezDqxrtjYC0dvsl0LVNKQOfjzjVo/edit?gid=0#gid=0) и создайте свою персональную копию.
2. Измените **«Настройки доступа»** (кнопка справа вверху) на **«Все, у кого есть ссылка» → «Комментатор»**, чтобы ревьюер мог оставлять комментарии.
3. Обязательно ознакомьтесь с форматом оформления тест-кейса (урок 2.4). Добавьте в шаблон недостающие поля. **Отклонение от формата не принимается.**
4. Откройте требования и дизайн в Figma. Декомпозируйте задачу на крупные части функционала (например, Поиск) и определите, какие техники тест-дизайна применимы.
5. Напишите тест-кейсы. Количество и полнота проверок регулируются требованиями ниже.

## Требования к проверкам
### Функциональности для тестирования (соответствуют экранам в Figma):
1. Поиск
2. Карточка объявления (проверьте отображение разных данных)
3. Новое объявление
4. Редактирование объявления
5. Вход
6. Регистрация
7. Профиль пользователя

### Базовый минимум для каждой страницы/функциональности:
- Требования учтены при написании проверок.
- Есть проверки на **позитивные сценарии** (основные функции работают).
- Есть проверки на **негативные сценарии** (основные функции при некорректных данных/действиях).
- Использованы изученные **техники тест-дизайна**:
    - Граничные значения
    - Классы эквивалентности
    - Таблица принятия решений
    - Попарное тестирование
    - Таблица переходов-состояний

### Правила оформления шагов:
- Используйте **конкретные значения**, а не абстрактные.
    - ❌ Неправильно: «ввести значение от 1 до 5»
    - ✅ Правильно: «ввести значение 3»

### Количество проверок:
- Ограничьтесь **3 проверками на функциональность** (выберите самые оптимальные).
- **Требуемое общее количество тест-кейсов — 21.**
    - *Снижение баллов предусмотрено за недостаточное количество тест-кейсов и за избыточность проверок (более 3 на одну функциональность).*

---

## Требования к оформлению
1. Все проверки оформляйте по **структуре тест-кейса из урока 2.4**.
2. Каждый обязательный атрибут тест-кейса должен быть описан в **отдельной ячейке**. Добавьте недостающие столбцы и озаглавьте их.
3. Для каждого тест-кейса укажите:
    - **Тип проверки:** негативная или позитивная.
    - **Техника тест-дизайна**, использованная из предложенного списка.
        - *Будьте готовы объяснить ревьюеру, как именно вы применили выбранную технику, и предоставить артефакты.*
4. Столбец **«Статус»** оставляйте незаполненным.
5. Тест-кейсы должны быть **легко читаемы и понятны** не только вам, но и другим участникам команды (менеджерам, разработчикам). Формулируйте шаги так, чтобы любой коллега мог их однозначно воспроизвести. **Это ключевой критерий при ревью.**
